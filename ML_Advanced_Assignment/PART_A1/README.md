## Applied / Coding Questions

### Q1 — Missingness Profiling & Correlation Heatmap
**Notebook:** `Question1.ipynb`

- **Task:** Compute per-column missingness percentages and produce a missingness correlation heatmap (via `missingno`) to visually diagnose whether missingness is patterned or random.
- **Approach:** Synthetic 10×6 DataFrame → missing counts/percentages → missingness indicators → correlation matrix → Seaborn heatmap + `missingno.matrix` + `missingno.heatmap`.
- **Result:** Missingness is **patterned**: Age–Glucose missingness correlation = 0.764; Blood_Pressure–Cholesterol = −0.429.

### Q2 — Mean Imputation vs MICE
**Notebook:** `Question2.ipynb`

- **Task:** Compare mean imputation against MICE (`IterativeImputer`) on a housing-price dataset; report downstream RMSE of a regression model under each strategy, holding model and CV folds constant.
- **Approach:** California Housing → inject 15% missing → 80/20 split → two pipelines (`SimpleImputer(mean)` + `LinearRegression` vs `IterativeImputer` + `LinearRegression`).
- **Result:** **MICE wins** — RMSE 0.8009 vs 0.8574 (mean). Improvement ≈ 6.6%.

### Q3 — Correct Imputation vs Data Leakage
**Notebook:** `Question3.ipynb`

- **Task:** Build a Pipeline that imputes only within each training fold during `cross_val_score`; then compute a "leaked" version (fit imputer on full dataset first) and quantify optimistic bias.
- **Approach:** California Housing → inject 20% missing → identical 5-fold KFold for both approaches → `Pipeline([SimpleImputer(median), LinearRegression])` (correct) vs pre-imputed full data (leaked).
- **Result:** Optimistic bias = **0.0013%** (tiny, because median is a very weak statistic to leak). Lesson: always put the imputer inside the pipeline.

### Q4 — Missingness Indicator + Logistic Regression
**Notebook:** `Question4.ipynb`

- **Task:** Add a missing-value indicator alongside median imputation, and compare Logistic Regression coefficients and interpretation with vs. without the indicator.
- **Approach:** Breast Cancer → inject 10% missing → two pipelines (median only vs median + `add_indicator=True`) → compare AUC and coefficients.
- **Result:** AUC **0.9878** (median only) vs **0.9812** (median + indicator). Under MCAR, indicators add noise; coefficient signs of indicators are spurious.

### Q5 — MCAR vs MAR vs MNAR Simulation
**Notebook:** `Question5.ipynb`

- **Task:** Simulate MCAR, MAR, and MNAR missingness on a complete dataset (ground truth known), then apply a statistical test and report whether it correctly detects the MCAR case and flags the others as non-MCAR.
- **Approach:** Diabetes dataset → three variants of missing `bmi` (MCAR, MAR conditioned on `age`, MNAR conditioned on `bmi`) → logistic-regression diagnostic predicting missingness from observed variables → AUC + boxplots.
- **Result:** MCAR AUC = **0.537** (≈ random → correctly detected as MCAR); MAR AUC = **0.600**; MNAR AUC = **0.587** (both correctly flagged as non-MCAR). MNAR confirmed visually by true-BMI vs missingness boxplot.

## EHR Missing Data Project

**Script:** `ehr_missing_data_project.py`

### What It Does

1. Loads Pima Indians Diabetes dataset (768 rows × 9 columns).
2. Converts clinically impossible zeros to `NaN` for Glucose, BloodPressure, SkinThickness, Insulin, BMI.
3. Simulates three missingness mechanisms:
   - **MCAR** on `SkinThickness` (~15%)
   - **MAR** on `BMI` (depends on observed `Age`, capped at 30%)
   - **MNAR** on `Insulin` (depends on true `Insulin`, capped at 35%)
4. Profiles missingness (counts, rates, heatmaps, correlation matrix).
5. Analyzes missingness vs target (diabetes outcome rate when missing vs observed).
6. Builds a **feature-specific leakage-free pipeline**:
   - MICE → `BMI` (MAR)
   - Median + missing indicator → `Insulin` (MNAR)
   - Median → all other features
7. Evaluates the final model on a held-out test set (ROC-AUC, Accuracy, Precision, Recall, F1).
8. Runs 5-fold cross-validation on the final pipeline.
9. Runs an **ablation study** comparing Mean, Median, Median+Indicator, and MICE.
10. Saves the fitted pipeline (`.joblib`) for reuse.

### Key Design Decisions

- **Leakage prevention:** All imputation lives inside `Pipeline` / `ColumnTransformer` objects and is re-fitted inside each CV fold.
- **Feature-specific repair:** Each mechanism gets a strategy that matches its statistical properties (MCAR → median; MAR → MICE; MNAR → median + indicator).
- **Simulation ground truth:** Because mechanisms are injected, the "correct" repair is known — making the ablation study meaningful.

## Overall Takeaways

1. **Visualize missingness first.** Heatmaps (Q1) and boxplots (Q5) quickly reveal whether missingness is random or patterned.
2. **Use MICE for MAR.** MICE exploits inter-feature relationships and clearly beats mean imputation (Q2).
3. **Prevent leakage.** Always place the imputer inside the pipeline; the magnitude of leakage depends on the imputer (Q3).
4. **Missingness indicators are not always helpful.** Under MCAR they add noise; under MAR/MNAR they preserve signal (Q4).
5. **Statistical diagnostics can distinguish mechanisms.** A simple logistic-regression predictability test correctly separates MCAR from MAR/MNAR (Q5).
6. **Feature-specific repair beats one-size-fits-all.** The EHR project shows that matching the imputation strategy to the missingness mechanism produces a principled, defensible pipeline.
